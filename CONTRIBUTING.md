# Contributing to rixl

## Layout

Everything under `sdk/` is generated by [Kiota](https://learn.microsoft.com/openapi/kiota/)
from the upstream OpenAPI spec. Do not hand-edit it; changes are overwritten on
the next generation.

- `sdk/rixl_client.py`: `RixlClient`, the root request builder.
- `sdk/<prefix>/…`: one package per URL prefix (`media`, `posts`, `feeds`,
  `auth`, `billing`, `analytics`, `organizations`, `platform`, `internal`), with
  directories mirroring path segments and `item/` for `{id}` placeholders.
- `sdk/models/`: request and response dataclasses.
- `sdk/kiota-lock.json`: records the spec hash and generator version the current
  output came from.
- `examples/`: standalone async scripts.

## Regenerating the SDK

Requires the [Kiota CLI](https://learn.microsoft.com/openapi/kiota/install).

```bash
./gen.sh
```

It fetches `rixlhq/openapi` from GitHub and regenerates `sdk/` with
`--clean-output`, so anything you left in that tree is deleted. The client class
is `RixlClient` and the generated namespace is `rixl_sdk`.

After regenerating:

1. Diff the builder tree for renamed or removed properties, since builder and `by_*`
   method names are derived from path segments, so a route change upstream
   renames part of the public surface, and that is breaking for consumers.
2. Check `sdk/models/` for renamed modules; model module paths are part of the
   public API because callers import request bodies directly.
3. Update `examples/` and the README snippets to match.

## Known generation and packaging problems

These are open issues, not settled behaviour. Anyone touching packaging should
start here.

- **`sdk/rixl_client.py` cannot be imported flat.** It uses relative imports
  (`from .media.media_request_builder import …`), but `pyproject.toml` declares
  `py-modules = ["rixl_client"]` with `package-dir = {"" = "sdk"}`, which installs
  it as a top-level module. Importing it then fails with "attempted relative
  import with no known parent package". The generated tree only works when it is
  imported as a package, and `gen.sh` names that package `rixl_sdk`. Packaging needs
  to place the output under a real `rixl_sdk/` package with an `__init__.py`.
- **`packages.find.include` does not match the tree.** It lists
  `["feeds*", "images*", "videos*", "models*"]`. There are no top-level `images`
  or `videos` packages, and `media`, `posts`, `platform`, `auth`, `analytics`,
  `billing`, `organizations` and `internal` are all excluded, so a built wheel
  is missing most of the SDK.
- **List responses have no `total`.** `ListImagesResponse`, `ListVideosResponse`
  and `ListPostsResponse` carry `limit` and `offset` but no total count, although
  the API returns one and other SDKs expose it. It is dropped somewhere between
  the proto `int64` and the generated Python model.
- **No typed error bodies.** Every operation is generated with a `None` error
  map, so all failures surface as a bare `APIError` and the structured error
  payload is discarded.
- **`examples/` is stale.** The scripts use a flat, pre-versioning surface
  (`client.images.get()`, `client.videos.upload.init.post()`, model imports like
  `models.internal_images_handler.upload_init_request`) that no longer exists in
  the generated code. They need rewriting against the current builder chains
  before they are referenced from the README again.

## Releases

Version lives in `pyproject.toml` and history in `CHANGELOG.md`. Bump the minor
version for new operations and the major version for renamed or removed ones.
